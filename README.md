# 采集调度策略管理工具

离线版采集调度策略配置工具，涵盖站点登记、模板编排、代理轮换、限速调节、反爬策略、增量水位与结果校验规则，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `scraper-strategy-studio:entries` 与
  `scraper-strategy-studio:schedule-state` 两项，或调用 `resetModule(模块)`。

## 漏触发补偿

调度规则停用期间错过的时间窗，在规则恢复时自动比对并补生成采集批次：

- **时间窗比对**：`src/domain/cron.ts` 解析 5 段 cron 表达式并展开调度时间窗；
  `src/domain/missed-window.ts` 结合生效时段、停用区间、已生成采集作业与补偿批次，
  对每个窗口给出「缺失待补 / 冲突待判定 / 补偿已承接 / 人工已承接 / 作业已承接」结论。
- **幂等补偿**：补偿批次按「规则编号 + 时间窗起点」唯一，重复恢复不会重复补同一窗口；
  批次沿「缺失 → 待执行 → 已归档」生命周期流转，冲突放弃的人工批次落到「已结束」。
- **冲突归属**：规则恢复补偿与人工补采命中同一窗口时，可选择规则恢复接管（生成唯一规则
  补偿批次、人工批次结束留证）或人工补采接管（保留人工唯一批次、规则侧不再补单），两种
  做法的来源、负责人与变更证据分别留痕。
- **任务衔接**：补跑作业统一回到任务编排的待执行队列，不重复创建普通调度作业；编排失败
  重试保留上一份确认记录，只重新入队。
- **可追溯**：停用/恢复事件围绕规则编号记录在独立的调度编排状态里，页面可查看停用区间、
  补偿时间窗与每个批次的完整变更证据链。
- 逻辑测试：`make test`（或 `frontend/scripts/test-compensation.ts`），覆盖 cron 展开、
  窗口判定、恢复幂等、冲突两种判定、补跑重试与生命周期，共 61 项断言。
